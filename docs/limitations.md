# 验证范围、资源限制与已知边界

## 能据实得出的结论

本次完成本机功能验收、两个独立浏览器会话的进度隔离、少量双线程请求竞争、断网恢复、真实测试进程重启和数据库一致性断言。最新自动化为 55 项 API/数据库/隔离、9 项浏览器通过；计数不是覆盖率，也不是可同时服务的用户数。

本机没有配置独立云服务器、分布式负载机或生产观测环境。本次没有做大用户量、持续高负载、突发注册洪峰和多节点部署测试，因此不声明最大并发用户数、QPS、延迟分位数、长稳运行时间或生产 SLA。“庞大用户同时考试时稳定”属于尚未验证的能力边界。

原题允许普通本地部署，不要求购买云服务。缺少云资源限制了可验证的部署和容量范围，但不是本地模拟并发请求的技术障碍。若后续在本机压测，结果也只能说明指定硬件和负载模型下的表现，不能直接外推生产环境。

## 同手机号注册与请求竞争

| 场景 | 当前处理或实际证据 | 不能据此宣称的内容 |
| --- | --- | --- |
| 同手机号先后重复注册 | `users.phone UNIQUE`；后端捕获唯一性冲突返回 409；手工视频及顺序重复注册测试通过 | 不能称为已测试多个请求同一瞬间竞争注册 |
| 同手机号同时注册 | 代码层使用数据库唯一约束控制重复账号，插入操作在事务中；尚无专门同步启动的竞争注册测试报告 | 不保证任何规模下均及时返回 409，也未测锁等待/资源耗尽时表现 |
| 双线程重复开考和同题提交 | 已有 `ThreadPoolExecutor(max_workers=2)` 测试，验证一个场次、一条答案和不重复推进 | 不是多进程、多机或高并发容量验证 |
| 双线程心跳 | 已验证同一时间段不会重复扣时、小数余额不被取整补回 | 不代表持续高频心跳下的吞吐上限 |
| 两用户同时使用页面 | 用户双浏览器录屏及自动化独立会话，进度与结束状态不互相覆盖 | 不代表大量用户同时注册、答题和交卷的容量 |

同手机号竞争注册可在隔离环境中用线程/进程加同步屏障模拟，不必先拥有云服务器或额外任务调度系统。数据库事务与唯一约束承担账号唯一性；后端处理请求的线程调度、应用扩容、后台任务队列是不同问题。本次最终材料整理不新增这一竞争实验，保留为明确未覆盖项。

后续可先在独立测试数据库上同时发送相同手机号的注册请求，检查只生成一个账号、成功/冲突响应分布、异常率及会话记录；再针对不同手机号、在线心跳、集中交卷逐级扩大负载并记录资源和延迟。以上是后续计划，不是本次结果，不得在服务实际考生的数据库或进程上执行。

## 数据、计时和产品边界

- 只持久化已提交答案、场次和服务器确认的剩余时间；当前未提交选择没有草稿自动保存。每个用户每套卷仅一次场次，交卷后不能重考。
- 断网/离开期间暂停计时，恢复保持最近确认的余额；不足一次心跳的未确认区间可能不扣，超过 4 秒的心跳间隔按中断处理。故意反复刷新、断网或后台节流可能获得额外思考时间；本次没有实现防作弊加分题。
- 原 v1 场次无在线时长历史，升级后首次恢复只为当前未提交题一次性按快照初始化时限，已交答案与完成状态不回退。新规则下不会每次刷新都补满。
- API 完成状态已冻结，重试不重复推进；最后一题已保存但响应丢失后，重试会返回已结束错误，刷新可以恢复完成页，尚未增加这一分支的专门交互优化。
- 多个普通标签页共享 Cookie，不能当成不同用户。同一账号多个设备/会话的竞争使用不属于本次已验证防作弊能力；小规模多用户验证使用不同账号及独立浏览器会话。
- 手机号只做格式校验与账号标识，不发送短信、不核验真实归属；不提供找回密码、管理后台、复杂计分或成绩分析。

## 部署与运维边界

SQLite 使用 WAL、外键和写事务，写操作仍需串行竞争锁。锁等待、scrypt 注册/登录计算量、每秒心跳、磁盘与内存都可能成为负载瓶颈，本次没有量化。尚未针对极端数据库锁竞争增加服务层排队、限流、负载隔离或完善错误恢复，不能承诺高负载下不会超时或报错。

当前已实测 Windows 和 Chromium 自动化。没有完成 Linux/macOS、移动端、多浏览器兼容矩阵、HTTPS 公网部署、多实例/多机数据库共享、磁盘损坏/断电容灾、容量压测或完整安全审计。README 的 Nginx 配置是部署参考，不能描述为已上线验证。缺少登录/注册限流、短信验证、会话自动清理及完善生产监控。

自动化隔离了数据、端口、源码快照、缓存及浏览器资料；CPU、内存和磁盘仍共享本机，不承诺零物理资源争用。有人作答时只使用隔离测试入口，不重装依赖、不改业务源码、不停止用户服务、不在系统或物理网卡层断网。

代码包包含依赖锁和样例配置，不包含离线依赖安装包；新环境首次安装需能够访问相应依赖源。没有声称在全新无缓存的另一台机器完成过一键安装验收。
