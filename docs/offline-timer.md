# 断网、刷新与续考计时修复

## 要求核对与问题

原始《笔试题说明.md》基本题要求 3 要求适配倒计时、超时切题和续考交互；验收第 5 条要求“在答题过程中刷新或重新进入页面，能够恢复已有进度；倒计时和超时切题行为与页面说明一致”。原说明及欢迎页均未明确规定断网期间必须继续计时。

旧实现以 `question_started_at + timeLimitSeconds` 作为服务器截止时间。这是实现时选定的规则，虽然写入了旧版设计说明，却不是题目给定的要求。断网刷新后旧代码返回剩余 0，前端立即空答切走当前题，用户无法继续作答。按本次用户明确指示改为连接中断后保留剩余时间，并同步更新页面说明和测试。

用户已把手动录制视频放在原工作目录的 `docs/reports/`，包括注册、登录、拒绝错误密码、单选多选超时提前交卷及多用户同时作答。本次只读取文件清单，不改写或删除这些视频；视频本身不作为断网修复已验证的证明，新增自动化报告单独存放于 `docs/reports/offline-timer/`。旧报告保留为历史结果。

## 当前规则与实现

- 每题初始时间来自开考快照。数据库持久化小数精度的剩余预算，刷新、重连、重复开始只恢复余额，不重新给满整题时间。
- 在线答题每秒一次心跳；服务器计算并扣除相邻确认之间的时间，最多允许 4 秒的正常调度/网络间隔。更长的空窗视为连接中断，整个空窗不扣时。没有后台任务在离线时持续扣时。
- 刷新/关闭/返回欢迎页期间没有心跳。续考接口保留上次确认的余额并重新锚定；联网恢复后先调用该接口，因此短暂断网接近截止时间也不会仅因离线耗时把题切走。
- 前端只显示服务器确认的剩余秒数。offline 事件、请求失败或 2.5 秒探测超时触发暂停提示；探测恢复后继续计时。没有浏览器成功收到的超时确认就不自动提交。单独的心跳绝不写答案或推进题号。
- 在线确认余额归零后自动提交空答并进入下一题。先前已在线耗尽的预算仍是 0，不因重连复活。服务器同样检查预算，不能用修改浏览器时钟伪造剩余时间。
- 心跳校验账号、场次及当前题号/题目；旧题延迟心跳不能消耗下一题时间。事务串行处理，多个请求不会重复扣除同一个时间段；已交卷场次拒绝心跳和答题写入。
- 已提交答案继续持久化。当前题尚未提交的选择仍只保留在当前页面，刷新丢失选择这一已有边界未改变。

这采用优先保护续考体验的取舍：断开前最后不足一次心跳的区间可能不计入预算，反复刷新或故意阻断连接也可能获得额外思考时间；浏览器后台节流超过 4 秒同样视为暂停。它不提供强防作弊保证，加分题仍为测试策略与自动化。实际请求丢失也无法精确证明网络在哪一毫秒中断，恢复以数据库最后已处理的预算为准。

## 数据库升级

`002_connected_timer.sql` 为场次新增 `question_remaining_seconds` 与 `timer_updated_at`，启动应用时按版本顺序自动升级；不删除账号、场次、题目快照、作答或完成状态。

旧版本没有在线累计时长记录，无法准确重建断网前余额。对于升级后首次恢复的旧进行中场次，仅当前尚未提交的题按原快照时限初始化一次；已提交题不回退、已完成场次不重开。初始化持久化后再次刷新不会重新给满时间。迁移和二次初始化均由自动化覆盖。

本次没有对正在服务用户的数据库执行迁移。升级前须在无用户作答的维护时段停止前后端并备份数据库目录；v2 数据库不能再交给旧 v1 应用运行，回退需使用升级前备份。

## 不打扰活动用户的开发与启用

修复分支为 `fix/offline-exam-timer`，独立 Git 工作目录为 `D:\Blue\intern-written-test-offline-fix`。原 `D:\Blue\intern-written-test` 的源文件、活动数据库及服务保持不变，所以原服务不会自动获得修复。

独立目录只复用原目录已安装的依赖和测试浏览器（工作区内目录链接），不安装/升级依赖、不复用依赖预构建缓存。所有实际测试写入自身 `.runtime/node_modules/test-runs/` 下；只用动态回环端口和新建的无界面浏览器会话，沿用数据库与网络守卫。没有模拟切断操作系统或物理网卡连接，没有重启用户的服务。

确认所有用户结束作答后，停止原前后端，在原项目目录执行以下步骤。必须先停止服务再备份和合并，避免 Vite 热更新与迁移打断作答：

```powershell
cd D:\Blue\intern-written-test
# 以下备份仅在 backend/data 存在时执行；默认包含 SQLite 及其附属文件。
New-Item -ItemType Directory -Force .runtime/backups | Out-Null
$examBackup = Join-Path '.runtime/backups' ('before-offline-timer-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
if (Test-Path -LiteralPath backend/data) { Copy-Item -LiteralPath backend/data -Destination $examBackup -Recurse }
git merge --ff-only fix/offline-exam-timer
npm run db:init
```

若使用自定义 `EXAM_DATABASE_PATH`，备份该文件所在目录，并在初始化和启动的终端沿用相同配置。然后分别在两个终端启动 `npm run dev:api` 与 `npm run dev`，重新进入页面。若原分支在修复期间另有提交，快进合并会拒绝，需先处理版本差异；不能通过强制重置覆盖他人改动。原目录未跟踪的手动视频不在修复分支中，但此次合并不会覆盖它们。
