# 测试策略与运行方法

测试以完整考试流程和数据一致性为重点。接口层检查权限、状态和数据库约束，浏览器层验证实际页面操作，手工测试补充多用户使用和页面交互。

## 范围与优先级

| 优先级 | 风险 | 验证方式与原因 |
| --- | --- | --- |
| P0 | 新用户无法完成考试 | 页面与接口分别覆盖注册、登录、开考、单选/多选和交卷，检查完整链路 |
| P0 | 用户数据串用或越权 | 使用独立登录会话，检查进度隔离及读取、提交、恢复、交卷的所有权 |
| P0 | 重试或并发造成重复写入 | 重复提交和双线程请求，检查答案唯一性及题号只推进一次 |
| P0 | 交卷后仍能修改 | 正常及提前结束后再次答题，检查接口拒绝且原记录不变 |
| P0 | 服务重启丢数据 | 重建应用及实际重启测试服务，检查账号、会话、答案和进度 |
| P0 | 自动化干扰在考用户 | 数据库和请求地址守卫、独立源码/缓存、活动锁及服务身份检查 |
| P1 | 刷新重置时间或断网丢题 | 注入服务端时钟检查余额；浏览器验证在线超时、离线刷新和请求失败 |
| P1 | 凭据校验或退出失效 | 错误密码、未登录请求、Cookie 轮换、过期及注销后重放 |
| P1 | 响应丢失导致重复操作 | 服务端保存后模拟丢失响应，重试检查只推进一次 |
| P2 | 参数或初始化异常 | 非法手机号、密码、题号、选项和分页；重复初始化及题目快照 |

接口测试使用 pytest、FastAPI TestClient 和真实文件 SQLite。时间边界通过注入服务器时钟验证，数据库不做 mock。浏览器测试使用 Playwright Chromium，通过实际 Vite 代理访问 FastAPI。

账号、密码和作答均使用合成数据。API 用例使用独立数据库，浏览器用例使用独立会话；示例业务题目时限为 60 秒，浏览器测试缩短为 8 秒。

## 执行

按 README 安装依赖后，在仓库根目录运行：

```powershell
npm run test:e2e:install
node scripts/test-all.mjs
```

浏览器只需首次安装。也可分别运行：

```powershell
npm run test:api
npm run test:e2e
```

完整入口先执行 API，再执行浏览器测试。失败返回非零退出码；浏览器使用一个 worker，不自动重试。

## 环境隔离

每轮测试在 `.runtime/node_modules/test-runs/<运行ID>/` 中创建源码快照、数据库、缓存、报告和浏览器资料。该路径避开开发服务的文件监听，测试不会因创建配置或 HTML 而触发在用页面更新。

测试前后端使用动态回环端口，排除 5173 和 8003。启动器校验服务身份，浏览器仅允许访问测试服务地址；数据库连接拒绝该次测试目录外的文件。只有测试自行创建的进程会被停止，测试用例中的服务重启也不操作在用实例。

测试与清理共用互斥锁，运行中目录不能被清理。依赖安装、业务源码修改和正式服务重启应在无用户作答时进行。测试仍与本机业务共享 CPU、内存和磁盘。

## 报告与清理

`.runtime/latest-validation.json` 保存完整执行结果，`latest-api.json` 和 `latest-e2e.json` 指向各轮目录。其中 `reports/` 保存 JUnit、控制台和 HTML 报告，`artifacts/` 保存截图及失败 trace。

完整测试成功后，可另行归档：

```powershell
.\.venv\Scripts\python.exe -B scripts/archive-test-reports.py --report-name reviewer-run
```

新报告位于 `docs/reports/reviewer-run/`。归档完成后，按运行 ID 清理测试数据：

```powershell
npm run test:clean -- --run 运行ID
```

不带 `--run` 时清理所有已结束的自有测试目录。活动目录、未知目录、数据库备份和依赖不在清理范围内。若异常退出留下锁，应先确认记录的测试进程已经结束。
