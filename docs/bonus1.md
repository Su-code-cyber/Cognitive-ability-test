# 加分题 1：AI 辅助测试策略与自动化测试

本项目选做加分题 1，使用 AI 辅助分析业务风险、编写自动化测试和定位失败原因。测试覆盖完整考试流程，并检查权限、重复请求、计时恢复和持久化。

## 实现

| 层次 | 工具及位置 | 重点 |
| --- | --- | --- |
| 接口与数据库 | pytest、FastAPI TestClient；`backend/tests/` | 注册登录、场次状态、越权、答案保存、计时和少量并发请求 |
| 服务进程 | 自建 HTTP 服务；`backend/tests/test_restart.py` | 实际停止和重启后保留账号、会话与作答进度 |
| 浏览器 | Playwright Chromium；`tests/e2e/` | 注册→退出→登录→开考→单选/多选→交卷，以及刷新、断网、超时和失败重试 |
| 测试隔离 | `scripts/test-env.mjs`、`scripts/run-tests.mjs` | 独立数据、服务、缓存和浏览器；防止误用在考用户的环境 |

测试使用真实数据库和服务。接口层注入时钟验证边界，浏览器层执行实际页面操作。优先级、测试数据及场景选择理由见 [测试策略](testing.md)。

## 运行与结果

准备依赖和浏览器后执行：

```powershell
node scripts/test-all.mjs
```

环境准备、单项执行、报告归档和安全清理见 [运行方法](testing.md#执行)。

最近一次完整运行中，55 项接口、数据库及隔离测试和 9 项浏览器测试全部通过。实际 JUnit、日志、截图和 HTML 报告位于 `docs/reports/offline-timer/`，详见 [验证报告](verification.md)。

测试过程中发现并修复了断网刷新后当前题被判超时、提交失败时清空选择和完成状态恢复等问题，同时验证了重复请求不重复推进题号。报告保留了相关失败记录与修复说明。

## 验证边界

已覆盖两个独立用户、小规模双线程请求竞争及错误恢复。未进行容量压测，也未单独验证同手机号同步竞争注册。更多边界见 [局限性](limitations.md)。
