| 2. 自动化测试实现 | 注册→登录→开考→单选/多选答题→交卷完整流程；账号、权限、状态、计时、重复提交、持久化及隔离防护边界 | `backend/tests/`、`tests/e2e/` |
| 3. 可复现运行方式 | 锁定依赖准备、顺序执行入口、单项命令、运行标识、报告归档及只清理已结束测试的方法 | 本文件、[README](../README.md) |
| 4. 测试结果与分析 | 实际 JUnit、逐项日志、浏览器 HTML 报告压缩包、截图、网络与环境隔离证据、已修复问题和剩余风险 | [实际验证](verification.md)、[本轮汇总](reports/bonus1/summary.json) |

## 范围、风险与优先级

优先验证影响业务有效性和数据正确性的 P0 风险，再验证计时、恢复和错误处理等 P1 风险。界面动画、视觉差异和高并发吞吐不作为本轮验收目标。

| 优先级 | 场景 | 主要断言与选择理由 |
| --- | --- | --- |
| P0 | 任意新用户完整完成考试 | 页面与接口均走真实注册、退出、登录、开考、答题、交卷；避免只有固定成功响应 |
| P0 | 两个用户独立作答与越权 | 同卷不同场次、独立 Cookie；恢复/进度/提交/交卷均检查所有权，防止数据串户 |
| P0 | 已结束状态不可修改 | 正常及提前交卷后写入拒绝，重复交卷不重写结束时间 |
| P0 | 重复与并发请求 | 同一题不重复插入、不多推进；用数据库唯一约束和实际两线程请求验证 |
| P0 | 服务重启持久化 | 只重启测试自己创建的进程，验证账号、会话、答案和进度均在 |
| P0 | 测试干扰活动用户 | 独立源码/数据库/缓存/端口/会话；拒绝开发库；运行中拒绝清理；旁路模拟用户在另一库测试重启后仍能继续 |
| P1 | 错误密码、重复注册与未登录 | 错误响应不产生错误数据，注销凭据不能重放 |
| P1 | 计时与续考 | 服务端时钟注入精确检查截止边界；真实浏览器等待超时自动切题 |
| P1 | 响应丢失与刷新 | 后端先保存再向浏览器返回模拟 503；重试恢复到当前题，避免假成功或重复推进 |
| P1 | 参数、快照和只读结果查询 | 非法题号/选项拒绝；题库修改不影响已开始场次；未提交与超时空答可区分 |

测试账号与密码均为源码中的合成数据，每个测试使用新 SQLite 文件或每轮独立数据库。即使测试手机号与活动用户恰好相同，也不会进入活动数据库。测试不读取或导入活动用户的账号、Cookie、试卷场次或浏览器个人资料。

## 不干扰正在作答用户的执行约束

1. 每轮目录为 `.runtime/node_modules/test-runs/<运行ID>/`。中间的 `node_modules` 是有意保留的隔离层：当前 Vite 默认忽略该路径，因此测试创建的 `tsconfig.json`、HTML 和缓存不会成为开发服务的热更新输入。测试验证了已安装 Vite 的实际忽略规则。
2. API 测试在源码快照中执行，数据库连接守卫拒绝本轮目录以外的文件；直接运行未配置的 pytest 会失败，不回退到开发库。
3. 浏览器测试也使用源码快照和独立 Vite 缓存；不加载开发 `.env.local`，覆盖继承的数据库、代理、Cookie 与调试环境配置。应用依赖只读取已安装版本，测试期间不安装/升级依赖、不运行生产构建。
4. 测试服务使用动态分配的回环端口，显式排除 5173 和 8003。浏览器只允许访问本轮两个地址，所有允许及拦截请求都有不含密码/Cookie的路线审计；开发地址的拒绝测试在发送 HTTP 之前执行。
5. 运行前校验前后端响应中的本轮专属标识，误占端口或响应来自其他服务时中止。绝不复用已有服务。
6. 浏览器每次使用全新上下文和运行目录内的临时资料，不操作用户正在考试的窗口或登录 Cookie。
7. 测试与清理共用互斥锁。清理只接受带本工具标记、已结束且没有活动锁的目录，拒绝链接路径、运行中目录和旧式未知目录。
8. 只停止本轮 `spawn` 返回的子进程 PID；不按端口、进程名称或“所有 Python/Node”批量停止服务。若子进程退出状态不确定，保留锁并报错，禁止自动猜测或强行清理。
9. API 与浏览器顺序执行，浏览器仅一个 worker、不自动重试，并尝试将自有进程设为低于正常优先级。不做压测。

不会为了验收而暂停活动服务、锁住活动数据库或回滚用户进度。活动用户正常提交可能使业务数据自然变化，因此用独立的旁路模拟用户、连接守卫和请求审计验证隔离，不把活动库简单的前后哈希相等当作唯一证明。

这里保证数据、服务、会话、缓存和文件监听的隔离。测试与业务仍共享物理机器的 CPU、内存及磁盘，不能声称资源占用为零；需要资源层面完全隔离时，在独立机器执行同一源码和合成数据即可，无需复制活动数据库。正在作答用户的真实倒计时仍正常流逝，不会因测试暂停或重置。

## 环境准备与执行

首次安装依赖按 README 执行，须在开始服务用户之前完成；不要在有人作答时重装 `.venv` 或 `node_modules`。当前开发机已有依赖和测试浏览器，不需要再次安装。

首次需要浏览器时执行一次：

```powershell
npm run test:e2e:install
```

完整验收入口（API 与浏览器串行执行）：

```powershell
node scripts/test-all.mjs
```

也可单独执行：

```powershell
npm run test:api
npm run test:e2e
```

失败返回非零退出码；没有自动重试或筛选失败用例。入口使用固定隔离配置，不接受将测试指向任意地址、任意数据库或任意 pytest 临时目录的覆盖参数。

每轮记录包含开始/结束时间、状态、测试代码 Git 提交、源码文件 SHA-256、实际目录和端口。最新入口为 `.runtime/latest-api.json`、`.runtime/latest-e2e.json`，完整验收汇总为 `.runtime/latest-validation.json`。

若从代码压缩包运行而没有 Git 元数据，提交号可以为 null，源码文件哈希仍会保留。

## 报告、归档和清理

每轮运行目录下：

```text
run.json                  # 代码、目录、状态与文件哈希
source/                   # 只含源码的快照，不含活动数据库或 .env
state/                    # 测试服务数据库
cases/                    # API 测试逐项临时数据库
tmp/                      # 临时文件与测试浏览器资料
vite-cache/               # 仅本轮前端缓存
reports/                  # JUnit、日志、HTML报告、隔离和路线审计
artifacts/                # 页面截图；失败时附截图和 trace
```

成功完整运行后，将报告归档到可随 Git 交付的位置：

```powershell
.\.venv\Scripts\python.exe -B scripts/archive-test-reports.py
```

固定交付证据在 `docs/reports/bonus1/`。HTML 报告以 `browser-report.zip` 提供，解压后打开 `index.html`；不把新 HTML 文件写入开发服务的活动源码树。归档不复制数据库、登录 Cookie 或浏览器个人资料。

清理指定的已结束测试，运行 ID 从命令输出或 latest 文件获取：

```powershell
npm run test:clean -- --run api-示例运行ID
npm run test:clean -- --run e2e-示例运行ID
```

不带 `--run` 时清理本工具所有已结束运行；先归档需要保留的报告。不会清理开发数据库、用户服务、虚拟环境、测试浏览器、旧式未知目录或活动测试。另一个测试执行中，清理直接失败，不等待其结束后再删除。

若意外断电留下锁，先阅读锁内 PID 和对应 `run.json`，确认相关测试子进程均已退出后再人工处理；工具不会自动按旧 PID 猜测并杀进程。正常完成或正常中断由启动器清理自己的子进程和活动锁。

## 问题、修复与剩余风险

已修复原界面的记录状态误判、失败前清空选择、同轮重复点击和仅信任本地缓存身份等问题。浏览器验证曾发现测试对中文按钮空格、图标名称和状态提交时序的假设错误，已有原始失败记录。

本轮进一步发现并修复：绕过入口可误用默认数据库、测试共用前端缓存、普通临时目录中的配置文件可能进入开发热更新监听、清理未排除活动测试、复用错误服务缺少身份确认等隔离缺口。最终实际结果与证据见 [verification.md](verification.md)。

未覆盖高负载容量、真实网络故障长时间恢复、移动端及多浏览器矩阵、公网 HTTPS、操作系统资源硬限额、系统级网络抓包或完整生产安全审计。当前 Windows 环境已实测，其他操作系统未实测。网络审计是测试客户端的路由审计，不等同于系统级抓包。
