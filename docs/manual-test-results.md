# 用户手动测试结果与录屏索引

本页整理 `docs/reports/` 当前 7 个 MP4。用户撤回了含个人信息的旧并行视频，并提供 `多用户并行+刷新页面.mp4` 替换；以实际文件名“页面”为准，不沿用旧文件及其观察结论。当前文件不再改名或修改内容；时长、格式、长度和 SHA-256 见 [录屏清单](reports/manual-video-manifest.json)。观察基于关键时间点抽帧，不代表逐帧、音轨、隐私无遗漏或数据库审计。

录屏没有嵌入准确 Git 提交号，不强行指定拍摄版本。前六个视频包含历史界面；替换后的 M7 欢迎页展示联网计时、连接中断保留余额的说明，且实际观察到刷新续考。刷新不等于真实断网，断网暂停的边界仍以自动化报告和设计说明为准。

## 与自动化证据的分工

M7 已补充刷新前后题号与剩余时间的可见比较，但手工视频没有单独证明重新登录后的精确余额、实际停止后端并重启、非法跨用户访问、六题保存后的数据库结果、相同请求的竞争执行，以及真实断网恢复全过程。这些项目中已有自动化记录的，见 [验收对应表](acceptance-matrix.md) 和 [最新报告](reports/offline-timer/summary.json)。

用户在手动断网刷新时报告了当前题被消耗时间、重连可能跳题的问题。该反馈没有独立 MP4，但完整可见会话保留了报告及后续修复过程，自动化随后复现并验证长断网、离线刷新和后端不可达的恢复规则。不能声称这 7 个录屏包含新版断网回归。

两浏览器正常操作不等于高并发压测。当前证据不能证明大量用户同时登录、每秒心跳、集中交卷或同手机号同时注册时的性能和稳定性；该边界见 [limitations.md](limitations.md)。

## 交付方式

原始录屏以普通 Git 文件随最终源码仓库交付，评审克隆后可直接用支持 MP4/H.264 的播放器打开。录屏中保留测试表单和浏览器界面；文档不重复列出其中账号或密码。没有将本机数据库、登录 Cookie、浏览器个人资料或密码存储导出加入仓库。
